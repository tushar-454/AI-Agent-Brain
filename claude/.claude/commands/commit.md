Generate a clean git commit message for staged changes:

1. Follow Conventional Commits format (`feat`, `fix`, `refactor`, `docs`, `style`, `test`, `chore`).
2. Keep the subject line under 50 characters, imperative mood, lowercase, no period.
3. Prioritize explaining **why** the change was made over just restating **what** lines changed.
4. If there is a body, wrap at 72 characters.
5. If `$ARGUMENTS` are provided, incorporate that context into the message.
